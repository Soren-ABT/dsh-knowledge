# dsh-knowledge v0.3.6 — Retrieval and release hardening

This release makes knowledge retrieval safer, more predictable, and easier to
verify across platforms. It also adds the project's first reproducible CI,
package, security, and retrieval-quality gates.

## Retrieval behavior

- Automatic retrieval and all 14 model tools now share one strict
  enabled-knowledge-base boundary. An explicit empty or all-stale selection
  returns no bases instead of silently widening to every base.
- Per-base `autoRetrieve` and `autoRetrieveWeight` overrides are persisted and
  enforced.
- The current user turn controls topic gating and base-name routing; recent
  turns only enrich the query, so an old topic cannot hijack a new question.
- Multi-query search normalizes and deduplicates the primary query plus at most
  three variants, fuses rankings with Reciprocal Rank Fusion, and invokes the
  reranker at most once.
- Search totals no longer inflate with the number of query variants.

## Tool and context safety

- Automatically injected chunks are framed as untrusted reference material
  and carry stable base, document, and chunk identifiers.
- Untrusted source metadata is normalized to one bounded line.
- Permanent base and document deletion now requires host approval.
- Tool schemas validate search mode, source types, query lengths, and invalid
  time ranges.
- Long document tools return bounded pages with explicit truncation and
  continuation offsets.
- Native search rendering emits each excerpt once while retaining canonical
  structured citations.

## Engineering and verification

- CI covers the exact Node 22.19 floor and Node 24, native installation on
  Windows/Linux/macOS, and packed-tarball installation and boot through the
  official DSH CLI on Windows/Linux.
- A dependency-free pre-install check requires explicit boolean build-policy
  decisions, preventing local caches from concealing clean-run failures.
- A machine-enforced production audit policy documents the current transitive
  Transformers/sharp advisory and rejects every unapproved high or critical
  finding.
- A deterministic bilingual corpus measures Hit@1/3, Recall@3, MRR, context
  recall, latency, and RSS without API keys or model downloads.
- Package verification checks exports, declarations, manifests, release files,
  forbidden content, and machine-path leakage.
- CONTRIBUTING, SECURITY, issue templates, a PR template, and a no-publish
  `release:check` command make maintenance and releases reproducible.

## Compatibility

- Node.js: `^22.19.0 || >=24.0.0`
- DSH compatibility anchor:
  `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`
- Full local-model support: Windows, Linux x64/arm64, and Apple Silicon.
- Intel macOS still requires a remote or Ollama embedding provider because the
  required ONNX native runtime is unavailable there.

Issue #5's Linux worker lifecycle correction was already released in 0.3.5.
Version 0.3.6 retains that fix and adds the retrieval and engineering changes
above.

## Verification

Before publishing, run:

```bash
npm run release:check
```

This command verifies the release but does not tag, push, publish to npm, or
create a GitHub Release.
