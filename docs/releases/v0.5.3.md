# dsh-knowledge v0.5.3 — 嵌入批次自适应、目录同步与设置修复

0.5.3 修复第三方嵌入服务的批次上限问题，补齐目录同步、模型运行状态和全局设置，并改善 Windows 元数据写入恢复与多查询召回。

## 嵌入批次与模型状态（#62 / #57）

- DashScope／百炼等 OpenAI 兼容服务可能只接受每次 20–25 条输入，低于默认批大小 32。收到输入条数超限错误后，普通分块和语义分块都会将实际失败批次减半，重试相同位置，并在该文档的后续批次沿用较小值。
- 保留已经完成的批次和向量顺序；单条输入仍被拒绝时停止拆分并报告错误，避免重复发送相同请求。
- 知识库设置新增批大小入口及 CPU 预设。本地普通和语义分块每批最多 8 段，明确的内存分配失败会逐步降批到 1；修改批大小本身无需重建知识库。
- 本地模型的下载／健康验证状态与内存驻留状态分开显示，支持空闲释放预设，并展示加载状态与耗时。

## 目录同步（#57）

- 支持显式重新扫描目录和重新绑定源路径，保留逐文件同步结果。新增文件嵌入失败会报告部分失败，已有失败文件即使内容未变化也可重试。
- 每个目录来源可选择手动同步，或每 5／15／60 分钟自动同步。既有来源默认保持手动模式，定时配置和最近结果持久化保存。
- 扫描与删除串行执行，同一来源的并发扫描合并处理；删除来源、知识库或卸载插件时停止相应定时器。

## 全局设置与多查询召回（#59）

- 设置面板区分“当前知识库”与“全局默认值”，支持搜索模式和关闭重排时的向量阈值。生效配置摘要只显示已经保存的值。
- 全局嵌入模型变更先检查所有继承该配置的知识库：已有模型且包含文档的库需要通过重建切换；符合条件的纯词法库会在来源和空闲检查通过后后台补齐向量。任一受影响的库无法切换时，整次更新被拒绝，保留旧配置。
- 单库覆盖继续优先；完全覆盖模型配置或显式禁用嵌入的知识库保持独立。
- 多查询向量检索先按余弦相似度筛选，再进行 RRF 融合；不再把融合后的排名分数误当作余弦分数过滤。重排结果仍按其相关度阈值处理。

## 写入恢复与依赖安全（#55）

- 知识库、文档和全局配置共用一条元数据写入链。`EPERM`、`EBUSY`、`EACCES` 按 20／50／100／200／400 ms 重试，最多写入 6 次；持续失败会明确报错并保留之前的元数据。
- 已加载的持久库遇到启动自愈写入失败时保留可读状态；后台恢复逐条隔离失败，恢复状态写入失败也不会产生未处理的拒绝或中止宿主。DSH 宿主自身的通用 `rename` 问题仍需上游处理。
- 升级 undici 至 **7.30.1**，修复已记录的安全告警；生产依赖审计继续拒绝所有高危／严重告警及不完整的审计输出。

## 升级说明

- 从 **0.5.2** 升级无需数据库格式迁移、重新下载模型或全库重建。
- 升级后请重建此前因嵌入批次超限而失败的文档。第三方接口用户也可在知识库设置中手动调小 `embeddingBatchSize`，例如设为 10；自动降批不修改保存的配置。
- 自动同步需要按目录来源主动开启；未开启的来源继续手动同步。
- `knowledge.json` 包含库名、文档记录和配置，不是可丢弃缓存。备份请同时保留 storage domain 元数据、SQLite 和 `knowledge-raw`；不需要为本次更新禁用 `resumeInterruptedOnStartup`。

## 验证

发布门槛包括版本与构建策略校验、生产依赖审计、类型检查、**647 项测试（53 个文件）**、检索基准、构建、发布包校验和四类 worker 协议冒烟测试。检索基准的主查询与多查询 Hit@1、Hit@3、Recall@3、Context Recall 和 Visible Evidence 均为 100%，未调整基准。

运行时代码已通过 Node.js **22.19／24／26** 质量检查、Ubuntu／Windows／macOS 原生检查，以及 Windows／Ubuntu 上 DSH **0.1.1-rc.2／0.2.0-rc.2** 的打包安装、启动与卸载检查。可选真实模型与托管 MinerU 推理仍需单独验收。

## English summary

- **Adaptive embedding batches (#62 / #57):** handle remote input-count caps in ordinary and semantic chunking, halve the actual failed request, preserve completed work and vector order, and stop splitting at one input. Expose batch controls and CPU presets; retain local allocation-error fallback and show model residency separately from downloaded readiness.
- **Directory sync (#57):** rescan or rebind directory sources, preserve per-file outcomes, retry unchanged failed files, and opt into per-source 5/15/60-minute schedules. Existing sources remain manual; scans and deletes are serialized and timers stop with their owner.
- **Settings and retrieval (#59):** expose global defaults and per-base settings, show saved effective values, validate every affected base before changing global embedding models, and keep overrides independent. Apply cosine thresholds before multi-query RRF fusion rather than filtering fused rank scores as cosine similarities.
- **Recovery and security (#55):** serialize metadata writes with bounded Windows lock retries, retain the previous metadata after persistent failure, and isolate startup/background recovery errors. Upgrade undici to 7.30.1 and retain strict production auditing.
- **Upgrade:** no database migration, model download or library-wide rebuild is required from 0.5.2. Rebuild documents whose embeddings previously failed; optionally lower `embeddingBatchSize` for third-party endpoints. Automatic sync is opt-in. Back up storage-domain metadata, SQLite and `knowledge-raw` together.
- **Validation:** 647 tests in 53 files, typecheck, production audit, retrieval benchmarks, build/package checks and four worker protocol smokes. The runtime passed Node 22.19/24/26, Linux/Windows/macOS and packed DSH 0.1.1-rc.2/0.2.0-rc.2 compatibility checks; optional real-model and managed MinerU inference remain separate.
