# dsh-knowledge v0.3.8 — Ordered evidence windows and bounded proactive retrieval

This release upgrades retrieval from a list of isolated chunks to a coherent,
diagnosable evidence chain. Search hits now carry ordered, token-bounded
context; models can continue reading directly from the hit anchor; and the
automatic first-token path has one explicit deadline and rerank policy.

The upgrade is additive and migration-free. Existing 0.3.7 databases,
embeddings, `SearchHit.text`, page-mode document reads, and callers that still
consume `siblingContext` continue to work.

## Ordered `ContextWindow`

- New search results include an optional `contextWindow` with `before`,
  `anchor`, and `after` excerpts in document order. Each excerpt identifies its
  chunk/index/heading, chunk-relative UTF-16 range, and truncation state; the
  window reports its estimated token count and whether more content exists on
  either side.
- The complete canonical hit remains in `SearchHit.text`.
  `siblingContext` is deprecated but retained throughout 0.3.x for wire and
  source compatibility.
- One shared composer supplies reranking, explicit search rendering,
  proactive previews, and evaluation. It stops at heading boundaries by
  default, centres oversized anchors around the query, removes exact adjacent
  overlap, and always preserves anchor evidence.
- Context is generated at retrieval time. v0.3.8 does not duplicate bridge
  text into chunks, the FTS index, or embeddings.

## Continue reading from a search hit

`knowledge_search` now exposes `chunkIndex` and one continuation hint. The
existing `knowledge_get_document` tool has two mutually exclusive modes:

- **Page mode**: omit anchors and continue using `chunkOffset` / `chunkLimit`.
  Pagination now uses a bounded SQLite LIMIT/OFFSET read instead of loading the
  complete document before slicing.
- **Context mode**: pass exactly one of `anchorChunkId` or `anchorIndex`, plus
  optional `before` / `after` (0–10), `maxTokens` (128–4096; default 1600),
  `focus` (up to 500 characters), and `crossHeading` (default false).

Page and context parameters cannot be mixed. A stale chunk id, wrong document,
disabled base, or invalid index fails explicitly instead of reading a different
chunk. Regular-expression results from `knowledge_read_document` also display
their character offsets and a direct follow-up instruction.

## Predictable proactive retrieval

- Automatic retrieval calls the lexical candidate path with service reranking
  disabled. It never starts a local cross-encoder before the first token. A
  configured remote reranker may run at most once, with zero retries, within
  one four-second end-to-end deadline.
- Provider timeout, crash, or failure preserves the original retrieval order.
  External cancellation exits immediately without injecting background or
  mutating throttle / dedup state.
- The current user turn always survives the 200-character query budget. A
  short or referential follow-up may add one history-aware lexical query, and
  the two rankings are fused with RRF.
- Seen chunks are removed before reranking and seat allocation. Same-topic
  follow-ups may contribute one new evidence item; new topics may contribute
  up to three.
- Naming a base with automatic retrieval disabled (or weight 0) no longer
  falls through to other bases. Exact identifiers are boundary-checked and
  must be visible in the injected evidence.
- Two-character CJK LIKE matches now receive positive normalized scores.
  Metadata allow-lists are fail-closed: `undefined` means unrestricted, while
  an explicit empty `docIds` list matches zero documents.

## Public compatibility shape

```ts
interface SearchHit {
  text: string                 // complete canonical anchor; unchanged
  contextWindow?: ContextWindow
  /** @deprecated retained through 0.3.x */
  siblingContext?: string
}

interface ContextWindow {
  anchorChunkId: string
  anchorIndex: number
  before: ContextChunkExcerpt[]
  anchor: ContextChunkExcerpt
  after: ContextChunkExcerpt[]
  estimatedTokens: number
  hasMoreBefore: boolean
  hasMoreAfter: boolean
}
```

No database migration, automatic reindex, model download, or additional
embedding pass runs during upgrade.

## Quality gates

Benchmark schema v2 exercises the actual model-visible search evidence and
automatic background against the deterministic bilingual 24-document,
40-question synthetic fixture. On that committed fixture, the release
baseline records:

- 100% Hit@1, Hit@3, Recall@3, MRR, and legacy Context Recall;
- 100% Visible Evidence Recall and Bridge Success@1;
- 100% `ContextWindow` coverage;
- zero evidence-order and hard-token-budget violations.

The dedicated Bridge Success@1 fixture deliberately keeps the answer out of
the top anchor, then requires it to survive both the top hit's serialized
context window and a real `getDocumentContext(anchorChunkId)` continuation.
It is not a claim that a live model autonomously completed the whole follow-up
tool trajectory. These deterministic fixture scores are regression gates, not
accuracy promises for private corpora or configured embedding/rerank
providers. Duplicate-token ratio and p50/p95 latency remain report-only
because shared CI machines are not performance-isolated.

## Deliberate non-goals

v0.3.8 does **not** claim to fix or change:

- vector fusion across knowledge bases that use incompatible embedding spaces;
- stale-vector signature policy;
- semantic chunk centroid/final-text embedding correctness;
- Issue #6 smart-chunk fragmentation or global chunk aggregation.

Ordinary smart chunking and `chunkOverlap` therefore keep their existing
behaviour. The new evidence window is query-time context composition, not a
change to stored chunk boundaries.
