# dsh-knowledge v0.5.0 — Structured Evidence and Experimental Managed MinerU

This release expands the document-processing pipeline with structured evidence and adds an optional, isolated MinerU deployment path. The existing cloud API and external self-hosted MinerU integration remain available.

## Highlights

- **Structured evidence from parse to answer.** Page and block references, table/formula structure, and inert image assets can travel through parsing, chunking, storage, retrieval context, and anchored reads. Evidence tools can continue from a specific chunk instead of repeatedly reopening unrelated sections.
- **Rechunk without reparsing.** Saved parse artifacts can be reused to produce a new chunk/index generation. Failed replacement keeps the previous usable generation available.
- **Optional managed MinerU — experimental.** The setup flow checks a selected CPython environment, previews verified model reuse and download size, honors separately configured Hugging Face and Python package sources, and installs into a dedicated environment. The active deployment pointer changes only after the candidate passes a real PDF parse probe.
- **Safer processing lifecycle.** Imports and rebuilds share processing paths, with bounded queue/state reporting and generation-aware recovery behavior.
- **UI and evidence workflow improvements.** Processing configuration and evidence views have clearer grouping, status messages, and navigation affordances while retaining existing controls.

## Verification and limits

The local release-candidate checks passed: typecheck, 454 Vitest tests, retrieval benchmark v2, structured regression tests, worker protocol smoke, build, package verification, release metadata verification, and the production dependency audit policy.

The audit currently permits two high-severity `sharp` advisories only through **2026-10-14** for the narrowly scoped `@huggingface/transformers > sharp` dependency path. This is a temporary exception, not a clean/no-vulnerability result, and must be reviewed before its deadline.

Real managed MinerU cold-install/parse runs on Windows and Ubuntu, live-browser settings acceptance, and the final clean-commit GitHub Actions run are still pending. Managed MinerU therefore remains **experimental**. This release does not claim certified OCR accuracy, all-platform support, or a successful real-model installation on every supported Python version.

## Upgrade notes

- Managed MinerU is opt-in. Opening settings or detecting Python does not install Python packages or download model files; installation requires an explicit preflight and confirmation.
- Python packages and model files use separate configurable sources. The selected endpoints are shown before installation; downloaded model files are verified against the pinned manifest.
- Existing cloud/self-hosted MinerU configuration remains supported. No automatic fallback from local processing to a cloud service is introduced.
- Existing data upgrade compatibility must be confirmed by the release-candidate upgrade checks before calling the release fully ready. No forced re-embedding or model download is intended by the new managed deployment flow.
