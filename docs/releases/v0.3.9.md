# dsh-knowledge v0.3.9 — Local-path source tracking and UI polish

This release turns local-path import into a durable, reindexable source
workflow and integrates a set of Ollama, theme, popover, localization, and
interaction improvements. It includes the community work from PRs #10–#13
plus maintainer hardening and regression coverage.

The upgrade is additive and migration-free. Existing v0.3.8 databases,
chunks, embeddings, retrieval contracts, uploads, URL imports, and model
configuration continue to work without an automatic reindex or model
download.

## Import files and directories by path

- Import one local file or a complete directory tree by absolute path. Every
  top-level file/directory source retains a stable source id, source kind, and
  original path for later inspection and reindexing.
- Directory rescans synchronize the source tree with disk: new files are
  imported, changed files are rebuilt, and vanished files are removed.
- Partial directory imports no longer hide individual failures. The service
  returns per-file errors and the management panel surfaces them while keeping
  successfully imported files.

## Targeted, failure-safe source tracking

- Repointing a source now updates exactly the selected top-level file or
  directory. Relative paths, ids from another base, nested children,
  unsupported source types, and file/directory kind mismatches fail
  explicitly.
- A repointed file is read from the new path during reindex. Changing from one
  extension to another also updates the parser identity, so (for example) an
  HTML replacement is parsed as HTML rather than as the old text source.
- Separate directory roots that contain the same relative file path keep
  distinct raw-source copies. Rescanning or deleting one root cannot remove
  the cached source that belongs to another root.
- Replacement reindexing stages new bytes and commits them only with the new
  document/chunks. If parsing, chunking, or persistence fails, the previously
  committed raw copy remains available for recovery.

## Ollama behavior

- An empty Ollama embedding base URL now falls back to the standard local
  endpoint, `http://127.0.0.1:11434`.
- OpenAI-compatible embedding providers still require an explicit URL; the
  fallback is intentionally provider-specific.
- Browsing installed Ollama models or starting a pull no longer changes the
  configured embedding provider/model behind the user's back.

## Interface and localization

- Root and nested portal popovers share viewport-aware placement so menus stay
  on-screen near the edges of the management panel.
- Theme tokens, menu dismissal, Toast interaction, and explicit model-setting
  behavior are more consistent and have policy-level regression tests.
- Chinese and English locale entries cover path import, source tracking,
  partial errors, and the integrated interface states.

## Compatibility and quality

- No database migration, automatic index rebuild, embedding pass, or local
  model download runs during upgrade.
- v0.3.8 `ContextWindow`, proactive retrieval, rerank, and anchored-reading
  behavior is unchanged.
- The release passes the complete typecheck and 322-test Vitest suite,
  retrieval benchmark v2, production dependency audit policy, deterministic
  build, package verification, and focused Windows filesystem scenarios for
  local-path import and source repointing.
