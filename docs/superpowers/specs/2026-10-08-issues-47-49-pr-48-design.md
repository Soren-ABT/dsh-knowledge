# Issues #47 / #49 and PR #48: investigation and repair

## Scope and decisions

Restore the Local Models settings section on DSH 0.2 while keeping optional
directory capabilities compatible with DSH 0.1. Remove the production audit
blocker by upgrading the actual dependency graph, and validate local text
inference with the new native runtime. No release, database migration or
automatic document reindex is part of this change.

The chosen approach combines the optional namespace lookup from PR #48 with
live directory capability resolution, and upgrades Transformers.js to the
published 4.3.1 package. Required injection of `remote.session` would leave
older hosts pending. Another sharp exception would retain vulnerable binaries
and a review deadline; a repository-only sharp override would not propagate to
an installed npm plugin's DSH profile.

## #47: reproduce the service gate, then correct the lookup

The 0.5.1 entry queried `ctx.get('remote')` and read `.session` while preparing
settings props. Cordis's associate proxy routes that property read through
the reading context's injection gate. `ctx.get('remote.session')` directly
queries the separately registered service and returns undefined if absent.
The namespace remains optional; the adapter also treats a refused legacy
Remote property read as missing capability.

The original PR regressions failed before the source fix, including the exact
`cannot get property "remote.session" without inject` error. Real Cordis
tests register the session in a sibling provider fiber, matching API gateway
registration. Providing it at the root would grant inherited access and hide
the bug. Tests also verify the calling plugin context survives method binding.

## PR #48: cached props exposed another lifecycle gap

The renderer caches root-slot injected props in a WeakMap. A static adapter
created at first injection therefore cannot discover later services or follow
replacement providers. Reopening a section does not guarantee new injection.
This gap exists even after the original PR removes the crash.

The production entry now passes a service resolver. Dynamic capability getters
preserve undefined when a capability is absent. Retained callbacks resolve the
current provider again when invoked, including the picker already passed to
MinerU. Static adapter arguments retain their existing behavior. An operation
invokes one current provider and propagates its errors without retrying another.

Six new or strengthened regressions failed against the original PR behavior:
late registration on the same cached object, retained picker and opener
replacement/withdrawal, current operation errors, and MinerU's retained picker
returning the old directory. They pass with live resolution.

Source: [DSH slot props cache](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/ui-renderer/src/client/scoped-slots.tsx#L251).

## #49: verify the dependency premise and remove the risk

[PR #48 CI run 37584048737](https://github.com/Soren-ABT/dsh-knowledge/actions/runs/37584048737)
failed all three Quality jobs solely at `audit:prod`. Native Windows/Linux/macOS
and all four packed DSH compatibility jobs passed. There were no submitted
reviews or unresolved review threads.

The new [librsvg advisory](https://github.com/advisories/GHSA-wq5f-xc86-pv6w)
affects sharp below 0.35.5. Official npm metadata contradicts the issue's
statement about Transformers 4.3.1: its published range is `sharp ^0.35.4`;
the latest 3.x version still uses `^0.34.1`. Pinning Transformers 4.3.1 resolves
sharp 0.35.5 and its ONNX runtime 1.30.0 in the updated lockfile.

The old two sharp exceptions are removed. Every high/critical advisory now
blocks. Investigation also reproduced audit-parser false passes for arrays,
unknown severity, missing/inconsistent counts and abnormal process exit with
an empty report. The policy now rejects all of these, plus error JSON, signals,
spawn errors and invalid JSON. Moderate findings remain reportable without
becoming exceptions. SECURITY.md is synchronized with the policy.

Actual native loading confirms sharp 0.35.5 with librsvg 2.63.2, libvips 8.18.7,
libheif 1.23.5, and Transformers' ONNX Node/Common 1.30.0. The separate OCR
runtime remains unchanged. No package-local sharp override is used.

Sources: [published Transformers metadata](https://registry.npmjs.org/@huggingface%2ftransformers/4.3.1),
[published sharp metadata](https://registry.npmjs.org/sharp/0.35.5).

## Runtime readiness and real inference

Embedding and rerank readiness records previously identified Transformers
3.7.x / ONNX 1.21.0. Both readers and writers now use one shared 4.3.1 / 1.30.0
identity. Six tests verify acceptance of current evidence and rejection of old
Transformers or ONNX evidence while cached weight files remain intact.

The embedding smoke checks finite 384-dimensional normalized BGE vectors,
semantic relevance and identical-batch inference after a fresh process starts
from cached weights. Equal batch shapes avoid normal dynamic-quantization
differences being mistaken for recovery failures. Children are terminated and
awaited before temporary caches are deleted.

Real BGE reranker inference returned relevant/irrelevant scores 0.9945 > 0.0000
in both the initial and fresh process. Real BGE embedding passed dimension,
normalization, relevance and fresh-process checks on Windows x64 / Node 24.16.0.
Official Hugging Face downloads timed out in this environment; successful runs
used the supported HF mirror and, for embedding, the configured local proxy.
The tests used isolated caches and did not alter the user's model directory.

- Full suite: 42 files, 544 tests passed. Focused directory tests: 37 passed.
- Typecheck, audit self-test and frozen dependency installation passed.
- Actual production audit: high 3 to 0, critical 0, moderate 1 (`sprintf-js`).
- Build, workspace/release metadata and packed-artifact verification passed.
- Retrieval benchmark retained 100% primary/multi-query/evidence metrics.
- All four bundled worker protocols passed.
- Real embedding and rerank inference/recovery passed as described above.

The original PR's cross-platform results are evidence for its original commit,
not the new dependency/lifecycle changes. The new changes still require the
repository's full CI matrix. Tests do not certify a visible native dialog or
file-manager launch. Published npm dependencies do not replace a user's DSH
profile lockfile; a profile retaining sharp 0.35.4 needs its dependency graph
refreshed and audited. Cached models need health revalidation after the runtime
upgrade. No claim of unchanged outputs across runtime versions is made.
