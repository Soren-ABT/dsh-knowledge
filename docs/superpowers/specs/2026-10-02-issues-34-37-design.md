# 0.5.0 fixes for issues #34–#37

The user requested reading all four open issues and their comments, fixing them
on top of the existing 0.5.0 MinerU branch, and preparing the result for merge
before they publish the release. No publication is part of this change.

## Findings and chosen behavior

- #34 has one comment locating the failure in the auto-retrieval background's
  legacy `plugin` source. Use a producer-owned `dsh-knowledge` source, preserving
  the user role, ordering, and retrieval
  gates. Test both message construction and acceptance by the v4 format boundary.
  Upstream's `recall` form specifically describes another session's history, so
  document retrieval does not claim that form.
- #35 has one comment confirming that the toggle and close button overlap the
  Windows title bar. Move the whole panel below the reported overlay rectangle;
  subscribe to geometry changes, and retain CSS titlebar environment variables
  as a fallback. Browser panels keep a zero inset. This also moves panel toasts
  into the safe content area without hard-coded Windows dimensions.
- #36 has no comments. Keep search instructions in the tool description and
  reduce the system section to available base names. Add `injectUsagePrompt`
  (default true) to deployment/runtime/per-base configuration and advanced
  settings. Turning it off does not disable tools or automatic retrieval.
- #37 has no comments and reports independent raster-memory and native-runtime
  failures. Explicitly destroy every mupdf pixmap, bound raster dimensions before
  allocation, retry allocation failures at smaller scales, and fail imports if
  any required page/image is omitted. Fork OCR inference into its own process,
  serialize inference, bound requests, and observe shutdown before deleting
  models. Crashes fail the document rather than DSH. Persist a bounded startup
  recovery attempt count; explicit rebuild starts a fresh attempt.

## Alternatives considered

Disabling auto-retrieval, applying a fixed 40px margin, or forcing every PDF to
1x would hide the symptoms but lose useful behavior or assume one environment.
Changing the DSH host would require a separate upstream release. The selected
fixes stay within the plugin and retain existing MinerU/evidence interfaces.

## Validation

Add focused regressions for producer-owned source admission, prompt suppression
and persistence, dynamic overlay geometry, pixmap disposal, large raster budgets,
incomplete OCR, child crash/timeout/shutdown, and bounded recovery. Run the full
suite, typecheck, build, retrieval benchmark, package/release metadata checks,
production audit, and emitted-companion protocol smoke. Use CI for the required
Windows/Linux/macOS matrix. Real-model OCR accuracy and managed MinerU acceptance
remain separate release gates and must not be inferred from offline tests.

Additional release blockers found during validation: remove retired OCR worker
bundles on incremental builds, and upgrade only the direct `undici` dependency
and lock entry to 7.30.0. The production audit retains its existing two `sharp`
exceptions until 2026-10-14. The built auto-retrieval message passed the actual
upstream v4 validator pinned at `639ed015397290b3745d163aafe02ffee4aa3f84`.
Focused browser checks used actual React components with mocked WCO geometry
and API responses; 40px/56px insets, zero browser inset, safe close/toggle/toast
placement, and saving only `injectUsagePrompt: false` were verified.

The first PR CI run exposed two existing MinerU branch blockers. Failed
re-preparation reported idle while persisting/unlocking the previous verified
installation; hold the busy state through cleanup and cover it with a blocked
real state-file rename. macOS temp paths contain system symlinks; canonicalize
only temporary test parents instead of changing production path admission.

The Windows packed-install job exposed the pinned public DSH CLI's HMR
create-then-check race. The temporary smoke profile explicitly enables the
existing HMR row with no module roots, allowing boot to settle that service
before configuration watching. Require one continuous healthy interval with
the process still alive; reject route success followed by exit, and reset the
interval after a failed response. This changes the smoke fixture, not the
plugin's host settings. Upstream reference:
https://github.com/deepseek-ai/deepseek-harness/discussions/7593.

The public legacy CLI's open HMR range also admits 1.0.19, which no longer
implements registerConfig. Install the public CLI into an isolated test root
with an exact 1.0.16 override. Extend packed-install CI to DSH 0.2.0-rc.2 on
Windows and Ubuntu, matching the version in #34's confirmation. Only legacy
0.1.1-rc.2 receives the temporary HMR patch; newer hosts retain their shipped
configuration. Both versions must satisfy the strengthened startup check.
