# dsh-knowledge v0.3.9 Release Implementation Plan

## Scope

Prepare, verify, commit, push, tag, and draft the GitHub release for v0.3.9.
The maintainer performs `npm publish`; the GitHub Release is published only
after npm registry verification.

## Implementation steps

1. Update `package.json` and `dsh.plugin.json` to `0.3.9`.
2. Add the 2026-09-02 v0.3.9 section at the top of `CHANGELOG.md`.
3. Create `docs/releases/v0.3.9.md`, following the v0.3.7/v0.3.8 release-note
   structure and crediting ThinkForge-core.
4. Update README/README.en installation examples and current-release summary
   without rewriting the v0.3.8 historical compatibility notes.
5. Run release metadata verification, focused local-path tests, full tests,
   benchmark, build, production audit, and package verification.
6. Inspect the npm tarball metadata and confirm required files include the
   v0.3.9 release note and all runtime workers.
7. Commit the release preparation. Run `npm run release:check` from the clean
   committed tree; fix and recommit if necessary.
8. Push `main`, identify the workflow run for the exact release commit, and
   wait for all required CI jobs. Treat the manual local-rerank job as allowed
   to skip.
9. Create annotated tag `v0.3.9` on the verified release commit and push it.
10. Create a GitHub Release Draft using `docs/releases/v0.3.9.md`.
11. Report the exact npm command and verified tarball metadata to the
    maintainer. Do not invoke `npm publish`.
12. After the maintainer reports publication, verify
    `npm view dsh-knowledge version` equals `0.3.9`, then publish the GitHub
    Release draft.

## Stop conditions

- Stop before tagging if local release gates or required GitHub CI fail.
- Stop before publishing the GitHub Release if npm does not report 0.3.9.
- Stop and request direction before changing a pushed release tag.
